Отчёт за 13 октября

Веб-зона: панель, сайт на ucoz, канал между машинами, кнопки управления сервером. Всё, что ниже, измерено; того, что не измерено, здесь нет.

Читать, если хочется коротко: главное — панель и сайт работают, канал между двумя компьютерами работает, а кнопки «поднять и опустить сервер» готовы и ждут, чтобы их открыли. Что не работает, написано честно в разделе «Чего нет».

2. Канал связи между двумя компьютерами

Сначала то, что не сработало

API PythonAnywhere не работает. Проверено девятью запросами: оба токена из файла с учётными данными, три адреса на токен — consoles, files, account. Ответ на все девять одинаковый: HTTP 404 и HTML-заглушка вместо JSON. Строить канал на том, что отвечает заглушкой, нельзя: такой канал будет работать только у того, кто умеет читать заглушки вместо данных.

Что сработало: FTP ucoz

Проверено на живой машине: вход, чтение списка, создание папки, запись файла, удаление. Значит канал построен на нём.

Устройство канала

Это почтовый ящик, а не сокет. Разница принципиальная: сокет требует, чтобы обе машины были онлайн одновременно. Ящик — нет. Второй компьютер заберёт сообщение через час, через день или через неделю.

  /link/box-<станция>/   непрочитанное для этой станции
  /link/read/<станция>/  забранное этой станцией, архив

Сообщение при чтении не удаляется, а переносится в архив: удаление оставило бы получателя без сообщения и без следа. У каждого сообщения подпись sha256 — она ловит обрыв при передаче, потому что молчаливо испорченный файл читается как сообщение.

Три дефекта, которые нашли проверки, а не чтение кода

  1. Разные папки у отправителя и получателя. Отправитель писал в out-<кому>, получатель читал in-<себя>. Обе папки выглядели правильно по отдельности, и сообщение не дошло бы никогда. Нашёл самотест, за одну строку.
  2. Проверка портила то, что проверяла. Функция сверки подписи забирала поле подписи у сообщения. Самотест печатал «подпись сошлась: ?» — прибор давал правильный ответ и сломанный предмет. Это худший вид прибора.
  3. Молчание про нечитаемое. Читались только файлы с расширением .json, и посторонний файл лежал в ящике, не попадая ни в «забрано», ни в «битые». Человек видел пустой результат и думал, что всё разобрано.

3. Кнопки «поднять» и «опустить» сервер

Локальное окно на этой машине: двойной клик по server_control.bat.

Три состояния, а не два

Лежит, работает, и — главное — порт занят чужим процессом. Без третьего состояния кнопка «Поднять» упрётся в занятый порт, и человек увидит ошибку запуска вместо причины.

Что подтверждено замерами

  • «Поднять» ждёт ответа API до 30 секунд. Запуск процесса ничего не значит: процесс может упасть сразу;
  • «Опустить» сначала мягко, через /shutdown, и ждёт освобождения порта 10 секунд. Жёсткая остановка появляется только после неудачи мягкой — убивать процесс раньше, чем человек понял причину, значит забрать у него решение;
  • если сервер ответил «останавливать нечем», это провал, а не успех.

Вход: первый заход — это админ

Пароль нигде не лежит: PBKDF2-SHA256, 200 000 итераций, случайная соль на каждый пароль, сравнение постоянного времени. Файл хранилища внутри .zwork по двум причинам сразу: писать можно только внутри WelcomeScreen, и .zwork уже стоит в .gitignore, то есть хэш физически не уедет в коммит.

Галочка «запомнить меня»

Хранит токен, а не пароль. Токен — подпись (логин, срок, случайность); из него пароль не восстановить. Это единственный из трёх вариантов, который не снимает пароль как защиту: пароль в файле перестаёт быть паролем, откроет файл — войдёт без ввода.

Роли

Обычный пользователь может поднять, опустить и открыть панель. Жёстко снимать процесс может только админ: это убийство чужого процесса по списку, и решает тот, кто заведует машиной. Свободная регистрация открыта, но админ может её закрыть одной кнопкой — иначе решение необратимо, закрывать будет некому.

4. Самый дорогой дефект этого дня

Галочка «запомнить меня» ломалась сама, примерно в 3,5 % запусков. Найдено повтором 400 раз, а не тестами: все проверки проходили.

Причина: ключ подписи — это 32 случайных байта, а bytes.strip() съедает не только пробел и перевод строки, но ещё \x0b и \x0c. Примерно в 5 % случаев такой байт оказывается на краю ключа, ключ читался короче, чем лежал, и подпись не совпадала.

Как нашёл: прибор сообщил, что токен не проходит проверку при верном сроке и верном ключе на диске. Тогда я стала печатать сам ключ при каждом вызове — два вызова подряд дали значения, съехавшие на один байт.

Починила: читаю байты как есть, пустоту проверяю длиной. Повтор-охота после починки: 800 проверок, 0 сбоев. Написала об этом отдельно, потому что дефект общий: у кого угодно с strip() на ключе он есть, и внешне выглядит как «иногда сессия слетает».

5. Ещё две находки того же рода

  • isalnum() в Python считает кириллицу буквами. Мой запрет на кириллицу в логине не работал: «вася» проходил как годный логин, а логин печатается в надписи и в журнале, где кириллица ломает разбор строк у того, кто читает.
  • Первая версия проверки подделки не делала ничего. Я подменял в токене строку «vasya», а логин там лежит в base64, и замена не находила ничего. Проверка была зелёной, не проверив ни одной подделки.

7. Чего нет

  • Оплата на сайте не подключена. Кнопка «Купить» ничего не берёт: ни карты, ни вебкошелька, ни перевода.
  • Заявки с сайта никуда не уходят. Сервера нет, ни одного сетевого запроса в коде: fetch, XMLHttpRequest, WebSocket — ноль вхождений.
  • Панель на хостинг не поднята. Файл панели весит 261 КБ, в консоль его не вставить; грузится перетаскиванием через раздел «Файлы».
  • API PythonAnywhere не работает, поэтому канал связи построен на FTP ucoz. Если API заработает, канал можно перевести на него, но смысл не изменится: ящик всё равно лучше сокета, потому что машины не обязаны быть онлайн одновременно.

9. Что дальше по моей зоне

  1. Поднять локальный рантайм и проверить панель вживую с данными, а не с заглушками.
  2. Прогнать харнесс панели после всех правок веба и убедиться, что он зелёный не на сломанном коде.
  3. Если API PythonAnywhere оживёт — перевести канал на него и оставить FTP как запасной.
  4. При появлении сервера на хостинге — настоящая регистрация с паролями на сервере, а не в браузере.

Отчёт собран из замеров, а не из отчётов о замерах. Каждое число выше можно повторить командой, и команды лежат рядом с кодом в репозитории.
